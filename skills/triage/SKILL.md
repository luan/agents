# Triage

Move vault artifacts through a small state machine. Load `$vault` before using `vlt`.

Every triage section written by an agent starts with:

```markdown
> *This was generated by AI during triage.*
```

## Roles

Categories:

- `bug` — something is broken
- `enhancement` — new behavior or an improvement

Stages:

- `needs-triage` — maintainer evaluation is pending
- `needs-info` — a specific answer or artifact is missing
- `ready-for-agent` — verified and bounded for autonomous implementation
- `ready-for-human` — requires continuing human judgment or access
- `wontfix` — deliberately closed

Record exactly one category and one stage in an artifact's `## Triage` section. Flag conflicting existing values before changing them.

## Reference

- [AGENT-BRIEF.md](AGENT-BRIEF.md) — durable agent briefs
- [OUT-OF-SCOPE.md](OUT-OF-SCOPE.md) — rejected enhancement decisions in the vault

## Invocation

Interpret natural requests such as:

- "Show me what needs triage"
- "Triage this research artifact"
- "Move this ticket to ready-for-agent"
- "What is ready for agents?"

## Show what needs attention

Use `find vault://current/?kind=...`, `search` scoped to `vault://current`, `read vault://current/<artifact>#related`, and `read vault://current/<artifact>#links` to build three oldest-first buckets:

1. Artifacts without a `## Triage` section.
2. `needs-triage` artifacts.
3. `needs-info` artifacts with new linked evidence or an updated body.

Show counts, artifact titles, stems, types, and a one-line summary. Let the maintainer select the next artifact.

## Triage one artifact

1. **Gather context.** Read the full artifact and linked context with `read vault://current/<artifact>#depth=2`, plus vault context and relevant decisions. Search the codebase by domain concept for existing behavior. Search decision artifacts for a matching out-of-scope choice.
2. **Recommend.** Present the category and stage recommendation with evidence. Wait for maintainer direction before mutating the vault.
3. **Verify the claim.** Reproduce a bug through `$diagnosing-bugs` or verify an enhancement against current code and behavior. Report confirmed, disproved, or insufficient evidence.
4. **Grill when needed.** Use `$grilling` and `$domain-modeling` one frontier round at a time until acceptance boundaries and vocabulary are settled.
5. **Apply the outcome** with `edit` on the artifact's `vault://current/<artifact>` resource:
   - `ready-for-agent` — create a `brief` artifact using [AGENT-BRIEF.md](AGENT-BRIEF.md), then link it with `vlt link <brief> <source> --type briefs --annotation "Agent-ready contract"`.
   - `ready-for-human` — create the same brief and state which judgment or access remains human-owned.
   - `needs-info` — record established facts and the smallest actionable request for missing evidence.
   - `wontfix` — record the reason; for a rejected enhancement, create or update an out-of-scope `decision` artifact following [OUT-OF-SCOPE.md](OUT-OF-SCOPE.md).
   - `needs-triage` — record partial progress and the next evaluation step.

## Triage section

```markdown
> *This was generated by AI during triage.*

**Category:** bug | enhancement
**Stage:** needs-triage | needs-info | ready-for-agent | ready-for-human | wontfix
**Reason:** concise evidence-backed explanation

### Established

- Resolved fact

### Needed

- Specific missing answer or artifact, when applicable
```

## Quick stage override

When the maintainer gives an explicit stage, trust the override. Confirm the artifact and vault mutations, then apply them. For `ready-for-agent`, offer to create the agent brief if one is not already linked.

## Resume

Read the existing triage section and linked artifacts before continuing. Carry forward established facts and ask only for information that remains missing.
